# Node.js Core

**Difficulty**: Intermediate  
**Revision Tip**: Practice the code examples in your terminal.

## 1. What is Node.js

**Q: What is Node.js?**

**Why asked**: Foundation of backend JavaScript.

**Answer:**  
Node.js is a runtime that allows us to run JavaScript on the server.  
It is built on Chrome’s V8 engine.  
It is mainly used for building backend applications and APIs.

**Example:**
```js
// Run this file with: node app.js
console.log("Hello from Node.js");
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    **Key points**
    - Single-threaded with event loop (non-blocking I/O)
    - Great for I/O heavy apps (APIs, real-time, chat)
    - Not ideal for heavy CPU tasks (use worker threads)

    **What makes it special**
    - Same language on frontend and backend
    - Huge npm ecosystem
    - Excellent for microservices and real-time apps
  </Accordion>
</Accordions>

## 2. Event Loop

**Q: What is the Event Loop?**

**Why asked**: Core of Node.js concurrency model.

**Answer:**  
The Event Loop is the heart of Node.js.  
It handles all asynchronous operations.  
It allows Node.js to perform non-blocking operations even though JavaScript is single-threaded.

**Example:**
```js
console.log("Start");

setTimeout(() => {
  console.log("Timeout");
}, 0);

console.log("End");
// Output: Start → End → Timeout
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    **Phases of the Event Loop** (simplified)
    1. Timers (setTimeout, setInterval)
    2. Pending callbacks
    3. Idle / prepare
    4. Poll (I/O)
    5. Check (setImmediate)
    6. Close callbacks

    **Microtasks vs Macrotasks**
    - Promises and `process.nextTick` run before the next event loop phase (microtasks).
    - `setTimeout` is a macrotask.

    ```js
    console.log("1");
    setTimeout(() => console.log("2"), 0);
    Promise.resolve().then(() => console.log("3"));
    console.log("4");
    // Output: 1 4 3 2
    ```
  </Accordion>
</Accordions>

## 3. Modules

**Q: What are modules in Node.js?**

**Why asked**: Code organization.

**Answer:**  
Modules are separate files that contain reusable code.  
We use modules to keep our code organized.  
We can export code from one file and import it in another file.

**Example:**
```js
// math.js
function add(a, b) {
  return a + b;
}
module.exports = add;

// app.js
const add = require("./math");
console.log(add(2, 3)); // 5
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    **CommonJS vs ES Modules**

    ```js
    // CommonJS (default in Node)
    module.exports = { add };
    const { add } = require("./math");

    // ES Modules ("type": "module" in package.json)
    export function add(a, b) { return a + b; }
    import { add } from "./math.js";
    ```

    **Module caching**
    Node caches modules after the first `require`. Subsequent requires return the same object.
  </Accordion>
</Accordions>

## 4. Global object

**Q: What is the global object in Node.js?**

**Why asked**: Environment awareness.

**Answer:**  
The global object is available everywhere in a Node.js application.  
Some common global objects are `console`, `process`, `Buffer` and `setTimeout`.  
We do not need to import them.

**Example:**
```js
console.log(global);
console.log(process.version);
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    **Important globals**
    - `process` → env, argv, cwd, exit
    - `Buffer` → binary data
    - `__dirname`, `__filename` (CommonJS)
    - `setTimeout`, `setInterval`, `setImmediate`

    ```js
    console.log(process.env.NODE_ENV);
    console.log(process.argv);
    console.log(__dirname);
    ```
  </Accordion>
</Accordions>

## 5. Callback Hell

**Q: What is Callback Hell?**

**Why asked**: Historical pain point & modern solutions.

**Answer:**  
Callback Hell happens when we write many nested callbacks.  
The code becomes difficult to read and maintain.  
We solve this problem by using Promises or async/await.

**Example:**
```js
// Bad (Callback Hell)
getData(function (a) {
  getMoreData(a, function (b) {
    getMoreData(b, function (c) {
      console.log(c);
    });
  });
});
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    **Modern solution with async/await**

    ```js
    async function load() {
      const a = await getData();
      const b = await getMoreData(a);
      const c = await getMoreData(b);
      console.log(c);
    }
    ```

    Promises and async/await flattened the pyramid of doom.
  </Accordion>
</Accordions>

## 6. Buffer

**Q: What is Buffer in Node.js?**

**Why asked**: Binary data handling.

**Answer:**  
Buffer is used to handle binary data in Node.js.  
It is very useful when we work with files, images or network data.  
Buffer is available globally.

**Example:**
```js
const buf = Buffer.from("Hello");
console.log(buf); // <Buffer 48 65 6c 6c 6f>
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    **Common operations**

    ```js
    const buf = Buffer.from("Hello World");
    console.log(buf.toString());        // Hello World
    console.log(buf.toString("hex"));   // 48656c6c6f...
    console.log(buf.length);

    const buf2 = Buffer.alloc(10); // empty buffer of size 10
    ```
  </Accordion>
</Accordions>

## 8. Streams

**Q: What are Streams in Node.js?**

**Why asked**: Efficient data handling.

**Answer:**  
Streams allow us to process data piece by piece.  
We do not need to load the entire file into memory.  
This makes it efficient for large files.

**Example:**
```js
const fs = require("fs");
const stream = fs.createReadStream("file.txt");
stream.on("data", (chunk) => {
  console.log(chunk);
});
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    **Types of streams**
    - Readable
    - Writable
    - Duplex
    - Transform

    **Why streams matter**
    Reading a 2GB file with `fs.readFile` would load everything into memory. Streams process it in chunks → much lower memory usage.
  </Accordion>
</Accordions>

## 9. createReadStream

**Q: What is createReadStream?**

**Why asked**: Practical stream usage.

**Answer:**  
createReadStream is used to read a file in small chunks.  
It returns a readable stream.  
It is memory efficient compared to reading the whole file at once.

**Example:**
```js
const fs = require("fs");
const readStream = fs.createReadStream("bigfile.txt");
readStream.on("data", (chunk) => {
  console.log("Received chunk");
});
```

## 10. async & await in Node.js

**Q: How do we use async and await in Node.js?**

**Why asked**: Modern async patterns.

**Answer:**  
We use async and await to handle asynchronous operations in a clean way.  
await pauses the execution until the Promise is resolved.  
It makes the code look like normal synchronous code.

**Example:**
```js
const fs = require("fs").promises;

async function readFile() {
  const data = await fs.readFile("file.txt", "utf8");
  console.log(data);
}
readFile();
```

<Accordions type="single">
  <Accordion title="Detailed Explanation + More Examples">
    Prefer the promise-based `fs.promises` API over callback style.

    ```js
    import { readFile, writeFile } from "fs/promises";

    async function copy() {
      const content = await readFile("input.txt", "utf8");
      await writeFile("output.txt", content);
    }
    ```
  </Accordion>
</Accordions>
