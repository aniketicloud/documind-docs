# Docker

**Difficulty**: Intermediate  
**Revision Tip**: Practice the commands on your machine.

## 1. Benefits of Docker

**Q: What are the benefits of Docker?**

**Why asked**: Why companies use containers.

**Answer:**  
Docker makes sure the application runs the same on every machine.  
It is lightweight compared to virtual machines.  
It helps in faster development and easy deployment.  
It also makes scaling easier.

**Example:**  
You can run the same Node.js app on your laptop and on the server without any environment issues.

<Accordions type="single">
  <Accordion title="More">
    Main benefits:
    - Consistency (works the same everywhere)
    - Isolation
    - Fast startup
    - Easy scaling
    - Clean dependency management
  </Accordion>
</Accordions>

## 2. Container

**Q: What is a Container?**

**Why asked**: Core Docker concept.

**Answer:**  
A container is a running instance of a Docker image.  
It contains the application and everything it needs to run.  
Containers are isolated from each other.

**Example:**
```bash
docker run node:18
```

<Accordions type="single">
  <Accordion title="More">
    Image = blueprint  
    Container = running instance of that blueprint

    You can run many containers from the same image.
  </Accordion>
</Accordions>

## 3. Docker Image

**Q: What is a Docker Image?**

**Why asked**: Building blocks of containers.

**Answer:**  
A Docker image is a template.  
It contains the application code and all its dependencies.  
We create containers from images.

**Example:**
```bash
docker build -t my-app .
```

<Accordions type="single">
  <Accordion title="More">
    Images are built from a `Dockerfile`.

    ```dockerfile
    FROM node:18
    WORKDIR /app
    COPY package*.json ./
    RUN npm install
    COPY . .
    CMD ["node", "index.js"]
    ```
  </Accordion>
</Accordions>

## 4. Docker Hub

**Q: What is Docker Hub?**

**Why asked**: Image distribution.

**Answer:**  
Docker Hub is a public registry for Docker images.  
We can push our own images there.  
We can also download official images like node, nginx, mysql etc.

**Example:**
```bash
docker pull node:18
```

<Accordions type="single">
  <Accordion title="More">
    ```bash
    docker login
    docker tag my-app username/my-app
    docker push username/my-app
    ```
  </Accordion>
</Accordions>

## 5. Lifecycle

**Q: What is the Docker container lifecycle?**

**Why asked**: Managing containers.

**Answer:**  
A container goes through different states.  
It starts from created, then running, then paused or stopped, and finally removed.  
We control these states using Docker commands.

**Example:**
```bash
docker start container_id
docker stop container_id
docker rm container_id
```

<Accordions type="single">
  <Accordion title="More">
    Useful commands:
    ```bash
    docker ps          # running containers
    docker ps -a       # all containers
    docker logs <id>   # view logs
    docker exec -it <id> bash  # enter container
    ```
  </Accordion>
</Accordions>

## 6. Background run container

**Q: How do you run a container in the background?**

**Why asked**: Practical usage.

**Answer:**  
We use the `-d` flag to run a container in detached mode.  
This means the container runs in the background.  
We can still check logs later.

**Example:**
```bash
docker run -d -p 3000:3000 my-app
```

<Accordions type="single">
  <Accordion title="More">
    `-d` = detached  
    `-p 3000:3000` = map host port to container port

    ```bash
    docker logs -f <container_id>  # follow logs
    ```
  </Accordion>
</Accordions>

## 7. Docker Swarm

**Q: What is Docker Swarm?**

**Why asked**: Orchestration basics.

**Answer:**  
Docker Swarm is a tool for managing multiple Docker containers.  
It helps in clustering and orchestration.  
It allows us to run containers across multiple machines.

**Example:**
```bash
docker swarm init
```

<Accordions type="single">
  <Accordion title="More">
    Swarm is Docker’s native clustering tool.  
    For bigger production setups, most teams use **Kubernetes** today.  
    Swarm is simpler and still useful for smaller projects.
  </Accordion>
</Accordions>
