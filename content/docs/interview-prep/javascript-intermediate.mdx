## 1. Closure

**Q: What is a closure?**

**Why asked**: Scope and memory management.

**Answer:**  
A closure is created when an inner function can access variables of the outer function.  
This works even after the outer function has finished running.  
It is very useful for data privacy.

**Example:**
```js
function outer() {
  let count = 0;
  return function inner() {
    count++;
    return count;
  }
}
const counter = outer();
console.log(counter()); // 1
console.log(counter()); // 2
```

<Accordions type="single">
  <Accordion title="More">
    **Why closures are powerful**

    The inner function keeps a reference to the outer function's variables even after the outer function has finished.

    **More examples**

    ```js
    // Private counter
    function createCounter() {
      let count = 0;
      return {
        increment() { count++; return count; },
        get() { return count; }
      };
    }

    const c = createCounter();
    console.log(c.increment()); // 1
    console.log(c.get());       // 1
    // count is private — cannot access from outside
    ```

    ```js
    // Common interview mistake with loops
    for (var i = 0; i < 3; i++) {
      setTimeout(() => console.log(i), 100); // 3 3 3
    }

    for (let i = 0; i < 3; i++) {
      setTimeout(() => console.log(i), 100); // 0 1 2
    }
    ```

    Closures are used in modules, event handlers, and React hooks (useState, useEffect).
  </Accordion>
</Accordions>

## 2. Destructuring

**Q: What is destructuring?**

**Why asked**: Modern JS syntax.

**Answer:**  
Destructuring means taking values from an array or object and storing them in variables in a simple way.  
It makes the code cleaner and shorter.

**Example:**
```js
const user = { name: "Aniket", age: 28 };
const { name, age } = user;
console.log(name); // Aniket
```

<Accordions type="single">
  <Accordion title="More">
    **Object destructuring**

    ```js
    const user = { name: "Aniket", age: 28, city: "Pune" };

    // Rename + default value
    const { name: fullName, age, country = "India" } = user;
    console.log(fullName, country); // Aniket India
    ```

    **Array destructuring**

    ```js
    const colors = ["red", "green", "blue"];
    const [first, second] = colors;
    const [, , third] = colors; // skip values

    // Swap variables
    let a = 1, b = 2;
    [a, b] = [b, a];
    ```

    **Function parameters**

    ```js
    function greet({ name, age = 18 }) {
      console.log(`Hello ${name}, age ${age}`);
    }
    greet({ name: "Aniket" });
    ```
  </Accordion>
</Accordions>

## 3. Object spread

**Q: What is the spread operator?**

**Why asked**: Immutability and copying.

**Answer:**  
The spread operator is used to copy or merge arrays and objects.  
We use three dots `...` for this.  
It is very common in modern JavaScript.

**Example:**
```js
const obj1 = { a: 1 };
const obj2 = { ...obj1, b: 2 };
console.log(obj2); // { a: 1, b: 2 }
```

<Accordions type="single">
  <Accordion title="More">
    **Copying objects (shallow)**

    ```js
    const original = { name: "Aniket", skills: ["JS", "React"] };
    const copy = { ...original };

    copy.name = "Rahul";
    console.log(original.name); // still "Aniket"

    // Nested arrays/objects are still shared (shallow copy)
    copy.skills.push("Node");
    console.log(original.skills); // ["JS", "React", "Node"]
    ```

    **Merging**

    ```js
    const defaults = { theme: "dark", lang: "en" };
    const userSettings = { theme: "light" };
    const final = { ...defaults, ...userSettings };
    // { theme: "light", lang: "en" }
    ```

    **Arrays**

    ```js
    const a = [1, 2];
    const b = [3, 4];
    const combined = [...a, ...b]; // [1, 2, 3, 4]
    ```
  </Accordion>
</Accordions>

## 4. this keyword

**Q: What is the `this` keyword?**

**Why asked**: Context binding.

**Answer:**  
`this` refers to the current object.  
In a method, `this` points to the object that owns the method.  
Its value depends on how the function is called.

**Example:**
```js
const person = {
  name: "Aniket",
  greet() {
    console.log(this.name);
  }
};
person.greet(); // Aniket
```

<Accordions type="single">
  <Accordion title="More">
    **Rules of `this`**

    1. In a method → object that owns the method
    2. Alone / simple function → global object (or undefined in strict mode)
    3. Arrow function → inherits from outer scope
    4. With `new` → the newly created object
    5. With call/apply/bind → whatever you set

    **Examples**

    ```js
    function show() {
      console.log(this);
    }
    show(); // window / global (non-strict)

    const obj = {
      name: "Aniket",
      show: function() { console.log(this.name); }
    };
    obj.show(); // "Aniket"

    const fn = obj.show;
    fn(); // undefined (lost context)
    ```
  </Accordion>
</Accordions>

## 5. call, apply, bind

**Q: What is call, apply and bind?**

**Why asked**: Controlling `this`.

**Answer:**  
These methods are used to set the value of `this`.  
call and apply run the function immediately.  
bind returns a new function with the bound `this`.

**Example:**
```js
function greet() {
  console.log(this.name);
}
const user = { name: "Aniket" };
greet.call(user); // Aniket
```

<Accordions type="single">
  <Accordion title="More">
    **call vs apply vs bind**

    ```js
    function introduce(city, country) {
      console.log(`${this.name} from ${city}, ${country}`);
    }

    const person = { name: "Aniket" };

    // call → arguments listed one by one
    introduce.call(person, "Pune", "India");

    // apply → arguments in an array
    introduce.apply(person, ["Pune", "India"]);

    // bind → returns a new function
    const boundFn = introduce.bind(person, "Pune");
    boundFn("India");
    ```

    **Real use case**
    Borrowing methods or fixing `this` in callbacks.
  </Accordion>
</Accordions>

## 6. Promise

**Q: What is a Promise?**

**Why asked**: Async handling.

**Answer:**  
A Promise is used to handle asynchronous operations.  
It has three states: pending, fulfilled and rejected.  
We use `.then()` for success and `.catch()` for error.

**Example:**
```js
const promise = new Promise((resolve, reject) => {
  resolve("Success");
});
promise.then(result => console.log(result));
```

<Accordions type="single">
  <Accordion title="More">
    **States**
    - pending → waiting
    - fulfilled → success (resolved)
    - rejected → error

    **Full example**

    ```js
    function fetchUser() {
      return new Promise((resolve, reject) => {
        setTimeout(() => {
          const success = true;
          if (success) resolve({ name: "Aniket" });
          else reject("Failed to fetch");
        }, 1000);
      });
    }

    fetchUser()
      .then(user => console.log(user.name))
      .catch(err => console.error(err))
      .finally(() => console.log("Done"));
    ```

    **Promise chaining**
    Each `.then` returns a new Promise, so you can chain them.
  </Accordion>
</Accordions>

## 7. async & await

**Q: What is async and await?**

**Why asked**: Modern async code.

**Answer:**  
async and await make asynchronous code look like normal synchronous code.  
await waits for a Promise to complete.  
It makes the code much cleaner than using `.then()`.

**Example:**
```js
async function getData() {
  const result = await Promise.resolve("Data received");
  console.log(result);
}
getData();
```

<Accordions type="single">
  <Accordion title="More">
    **Basic pattern**

    ```js
    async function loadUser() {
      try {
        const res = await fetch("/api/user");
        const data = await res.json();
        console.log(data);
      } catch (err) {
        console.error("Error:", err);
      }
    }
    ```

    **Parallel vs sequential**

    ```js
    // Sequential (slower)
    const a = await fetchA();
    const b = await fetchB();

    // Parallel (faster)
    const [a, b] = await Promise.all([fetchA(), fetchB()]);
    ```

    An `async` function always returns a Promise.
  </Accordion>
</Accordions>

## 8. IIFE

**Q: What is IIFE?**

**Why asked**: Scoping tricks.

**Answer:**  
IIFE means Immediately Invoked Function Expression.  
It is a function that runs as soon as it is defined.  
It is useful to create a private scope.

**Example:**
```js
(function () {
  console.log("I run immediately");
})();
```

<Accordions type="single">
  <Accordion title="More">
    **Why use IIFE?**
    Before modules existed, IIFE was the main way to create private variables.

    ```js
    const counter = (function () {
      let count = 0;
      return {
        inc() { return ++count; },
        get() { return count; }
      };
    })();

    console.log(counter.inc()); // 1
    // count is completely private
    ```

    Modern code uses modules (`import`/`export`) instead of IIFE in most cases.
  </Accordion>
</Accordions>

## 9. Scope

**Q: What is scope?**

**Why asked**: Variable visibility.

**Answer:**  
Scope means the area where a variable can be accessed.  
There is global scope and local scope.  
Variables declared inside a function are local to that function.

**Example:**
```js
let globalVar = "I am global";

function test() {
  let localVar = "I am local";
}
```

<Accordions type="single">
  <Accordion title="More">
    **Types of scope**
    - Global scope
    - Function scope
    - Block scope (`let` / `const`)
    - Module scope

    **Lexical scope**
    Inner functions can access outer variables (this is the foundation of closures).

    ```js
    function outer() {
      const msg = "Hello";
      function inner() {
        console.log(msg); // can access
      }
      inner();
    }
    ```
  </Accordion>
</Accordions>

## 10. Class vs Object

**Q: What is the difference between class and object?**

**Why asked**: OOP concepts.

**Answer:**  
A class is a blueprint.  
An object is a real instance created from that class.  
We use the `new` keyword to create an object from a class.

**Example:**
```js
class Person {
  constructor(name) {
    this.name = name;
  }
}
const p1 = new Person("Aniket");
```

<Accordions type="single">
  <Accordion title="More">
    **Class is just syntactic sugar**

    Under the hood JavaScript still uses prototypes.

    ```js
    class Person {
      constructor(name) {
        this.name = name;
      }
      greet() {
        console.log(`Hi ${this.name}`);
      }
    }

    const p = new Person("Aniket");
    p.greet();

    console.log(typeof Person); // "function"
    console.log(p instanceof Person); // true
    ```
  </Accordion>
</Accordions>

## 11. Prototype

**Q: What is prototype in JavaScript?**

**Why asked**: Inheritance mechanism.

**Answer:**  
Every object in JavaScript has a prototype.  
The prototype is used to share properties and methods.  
This is the base of inheritance in JavaScript.

**Example:**
```js
function Person(name) {
  this.name = name;
}
Person.prototype.greet = function () {
  console.log("Hello " + this.name);
};
```

<Accordions type="single">
  <Accordion title="More">
    **Prototype chain**

    When you access a property, JS looks on the object first, then on its prototype, then further up the chain until `Object.prototype`.

    ```js
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function () {
      console.log(`${this.name} makes a sound`);
    };

    const dog = new Animal("Tommy");
    dog.speak(); // uses the method from prototype
    ```

    All instances share the same prototype methods → memory efficient.
  </Accordion>
</Accordions>

## 12. Object Inheritance

**Q: How does inheritance work in JavaScript?**

**Why asked**: Prototypal inheritance.

**Answer:**  
JavaScript uses prototypal inheritance.  
One object can inherit properties and methods from another object.  
We can also use the `class` and `extends` keywords.

**Example:**
```js
class Animal {
  speak() {
    console.log("Animal sound");
  }
}
class Dog extends Animal {}
const d = new Dog();
d.speak(); // Animal sound
```

<Accordions type="single">
  <Accordion title="More">
    **Modern way (class)**

    ```js
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      speak() {
        console.log(`${this.name} barks`);
      }
    }

    const dog = new Dog("Bruno");
    dog.speak(); // Bruno barks
    ```

    **Old way (prototype)**

    ```js
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function () { /* ... */ };

    function Dog(name) {
      Animal.call(this, name);
    }
    Dog.prototype = Object.create(Animal.prototype);
    ```
  </Accordion>
</Accordions>

## 13. Design Pattern

**Q: What are design patterns?**

**Why asked**: Code architecture.

**Answer:**  
Design patterns are ready-made solutions for common problems in code.  
They help us write clean and reusable code.  
Common patterns are Module pattern, Singleton and Observer.

<Accordions type="single">
  <Accordion title="More">
    **Common patterns in JS**

    - **Module Pattern** → private + public methods (IIFE or ES modules)
    - **Singleton** → only one instance
    - **Observer / Pub-Sub** → event-driven (used heavily in frontend)
    - **Factory** → create objects without `new`
    - **Constructor / Prototype** → classic object creation

    Example of simple Module:

    ```js
    const calculator = (function () {
      let result = 0;
      return {
        add(n) { result += n; },
        get() { return result; }
      };
    })();
    ```
  </Accordion>
</Accordions>
