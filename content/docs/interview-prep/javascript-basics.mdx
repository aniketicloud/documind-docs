# JavaScript Basics

**Difficulty**: Beginner  
**Revision Tip**: Revise these daily for 1 week.

## 1. null & undefined

**Q: What is the difference between null and undefined?**

**Why asked**: To check if you understand variable states.

**Answer:**  
Undefined means a variable is declared but we have not given any value yet.  
Null means we have intentionally set the value as empty.  
JavaScript gives undefined by default.  
We set null ourselves.

**Example:**
```js
let a;
console.log(a); // undefined

let b = null;
console.log(b); // null
```

<Accordions type="single">
  <Accordion title="More">
    **Deeper understanding**

    - `undefined` is a type and a value. It means "this has not been assigned".
    - `null` is an object type (yes, famous JS quirk) that means "intentionally empty".
    - `typeof null` returns `"object"` — this is a long-standing bug in JavaScript.
    - `typeof undefined` returns `"undefined"`.

    **More examples**

    ```js
    let x;
    console.log(x === undefined); // true
    console.log(x == null);       // true (loose equality)

    let y = null;
    console.log(y === null);      // true
    console.log(y == undefined);  // true (loose)
    console.log(y === undefined); // false (strict)
    ```

    **Common interview follow-ups**
    - Why is `typeof null === "object"`?
    - When should you use `null` vs `undefined`?
    - Prefer `=== null` or `== null`? (Many prefer `== null` to catch both)
  </Accordion>
</Accordions>

## 2. == and ===

**Q: What is the difference between == and ===?**

**Why asked**: To check type coercion knowledge.

**Answer:**  
== checks only the value.  
=== checks both value and type.  
We should always use ===.  
It avoids unexpected results.

**Example:**
```js
5 == "5"   // true
5 === "5"  // false
```

<Accordions type="single">
  <Accordion title="More">
    **How == works**

    When types are different, JavaScript converts one side (type coercion) before comparing.

    **More examples**

    ```js
    0 == false        // true
    0 === false       // false

    null == undefined // true
    null === undefined // false

    "" == 0           // true
    "" === 0          // false

    [] == false       // true (array becomes empty string, then 0)
    [] === false      // false
    ```

    **Best practice**
    Always use `===` and `!==` unless you specifically want type coercion (rare).
  </Accordion>
</Accordions>

## 3. typeof & type casting

**Q: What is typeof and type casting?**

**Why asked**: Basic type handling.

**Answer:**  
typeof tells us the data type of a value.  
Type casting means converting one type into another type.  
We can convert string to number or number to string.

**Example:**
```js
typeof 10        // "number"
Number("20")     // 20
String(30)       // "30"
```

<Accordions type="single">
  <Accordion title="More">
    **typeof results**

    ```js
    typeof 42           // "number"
    typeof "hello"      // "string"
    typeof true         // "boolean"
    typeof undefined    // "undefined"
    typeof null         // "object"  (bug)
    typeof {}           // "object"
    typeof []           // "object"
    typeof function(){} // "function"
    typeof Symbol()     // "symbol"
    typeof 10n          // "bigint"
    ```

    **Common casting methods**

    ```js
    // String to Number
    Number("123")     // 123
    parseInt("123px") // 123
    +"123"            // 123 (unary plus)

    // Number to String
    String(123)       // "123"
    (123).toString()  // "123"
    123 + ""          // "123"

    // To Boolean
    Boolean(1)        // true
    Boolean(0)        // false
    !!"hello"         // true
    ```
  </Accordion>
</Accordions>

## 4. map vs forEach

**Q: What is the difference between map and forEach?**

**Why asked**: Array method understanding.

**Answer:**  
forEach is used only to loop through an array.  
It does not return anything.  
map also loops through the array.  
But map returns a new array.

**Example:**
```js
const numbers = [1, 2, 3];

numbers.forEach(n => console.log(n));

const doubled = numbers.map(n => n * 2);
// [2, 4, 6]
```

<Accordions type="single">
  <Accordion title="More">
    **Key differences**

    | Feature       | forEach          | map                |
    |---------------|------------------|--------------------|
    | Return value  | `undefined`      | New array          |
    | Chainable     | No               | Yes                |
    | Purpose       | Side effects     | Transform data     |

    **More examples**

    ```js
    const users = [
      { name: "Aniket", age: 28 },
      { name: "Rahul", age: 25 }
    ];

    // forEach - just print
    users.forEach(u => console.log(u.name));

    // map - create new array of names
    const names = users.map(u => u.name);
    // ["Aniket", "Rahul"]

    // map is chainable
    const upper = users
      .map(u => u.name)
      .map(n => n.toUpperCase());
    ```

    **When to use which**
    - Use `map` when you need a new array.
    - Use `forEach` when you only want to do something (log, update DOM, etc.).
  </Accordion>
</Accordions>

## 5. slice & splice

**Q: What is the difference between slice and splice?**

**Why asked**: Mutation knowledge.

**Answer:**  
slice does not change the original array.  
It just returns a part of the array.  
splice changes the original array.  
We can add or remove items using splice.

**Example:**
```js
const arr = [1, 2, 3, 4];

arr.slice(1, 3);   // [2, 3]  (original remains same)
arr.splice(1, 2);  // removes 2 items from index 1
```

<Accordions type="single">
  <Accordion title="More">
    **slice(start, end)** – non-mutating

    ```js
    const fruits = ["apple", "banana", "mango", "orange"];

    fruits.slice(1, 3);     // ["banana", "mango"]
    fruits.slice(2);        // ["mango", "orange"]
    fruits.slice(-2);       // ["mango", "orange"]
    console.log(fruits);    // original unchanged
    ```

    **splice(start, deleteCount, ...items)** – mutating

    ```js
    const nums = [10, 20, 30, 40, 50];

    // Remove 2 items starting at index 1
    nums.splice(1, 2);      // returns [20, 30]
    // nums is now [10, 40, 50]

    // Remove 1 item and insert new ones
    nums.splice(1, 1, 25, 35);
    // nums is now [10, 25, 35, 50]
    ```

    **Remember**: `slice` = copy/part, `splice` = change original.
  </Accordion>
</Accordions>

## 6. Hoisting

**Q: What is hoisting?**

**Why asked**: JS execution order.

**Answer:**  
Hoisting means JavaScript moves variable and function declarations to the top of the scope.  
Only the declaration is moved.  
The actual value assignment stays in its place.

**Example:**
```js
console.log(a); // undefined
var a = 10;
```

<Accordions type="single">
  <Accordion title="More">
    **How it works**

    Before code runs, JS scans and "hoists" declarations.

    ```js
    // What you write
    console.log(a);
    var a = 5;

    // What JS roughly does
    var a;          // declaration hoisted
    console.log(a); // undefined
    a = 5;          // assignment stays
    ```

    **Function declarations are fully hoisted**

    ```js
    sayHello(); // works

    function sayHello() {
      console.log("Hello");
    }
    ```

    **let and const are hoisted but in Temporal Dead Zone**

    ```js
    console.log(b); // ReferenceError
    let b = 10;
    ```

    You cannot access `let`/`const` before their declaration line.
  </Accordion>
</Accordions>

## 7. Mutable & Immutable

**Q: What is mutable and immutable?**

**Why asked**: Data mutation concepts.

**Answer:**  
Mutable means we can change the value after creating it.  
Arrays and objects are mutable.  
Immutable means we cannot change the value.  
Strings and numbers are immutable.

**Example:**
```js
let str = "hello";
str[0] = "H";     // does not change

let arr = [1, 2];
arr[0] = 10;      // changes
```

<Accordions type="single">
  <Accordion title="More">
    **Primitive types are immutable**

    ```js
    let name = "Aniket";
    name[0] = "a";
    console.log(name); // still "Aniket"

    let num = 10;
    num = 20; // this creates a new value, old 10 is gone
    ```

    **Objects and arrays are mutable**

    ```js
    const user = { name: "Aniket" };
    user.name = "Rahul"; // allowed (const protects the reference, not the content)
    console.log(user); // { name: "Rahul" }

    const list = [1, 2, 3];
    list.push(4); // allowed
    ```

    **Why it matters in React**
    We treat state as immutable. We create new objects/arrays instead of changing existing ones so React can detect changes.
  </Accordion>
</Accordions>

## 8. let vs var

**Q: What is the difference between let and var?**

**Why asked**: Scoping rules.

**Answer:**  
var is function scoped.  
let is block scoped.  
let is safer and modern.  
We should prefer let over var.

**Example:**
```js
if (true) {
  var a = 10;
  let b = 20;
}
console.log(a); // 10
console.log(b); // Error
```

<Accordions type="single">
  <Accordion title="More">
    **Scope difference**

    ```js
    function test() {
      if (true) {
        var x = 1;
        let y = 2;
        const z = 3;
      }
      console.log(x); // 1 (function scoped)
      console.log(y); // ReferenceError (block scoped)
    }
    ```

    **Redeclaration**

    ```js
    var a = 1;
    var a = 2; // allowed

    let b = 1;
    let b = 2; // SyntaxError
    ```

    **Hoisting behavior**
    - `var` is hoisted and initialized with `undefined`.
    - `let` and `const` are hoisted but stay in Temporal Dead Zone until the line runs.

    Prefer `const` by default, then `let` when you need to reassign. Avoid `var`.
  </Accordion>
</Accordions>

## 9. Arrow function

**Q: What is an arrow function?**

**Why asked**: this binding.

**Answer:**  
Arrow function is a short way to write a function.  
It does not have its own `this`.  
It takes `this` from the surrounding scope.

**Example:**
```js
const add = (a, b) => a + b;
console.log(add(2, 3)); // 5
```

<Accordions type="single">
  <Accordion title="More">
    **Syntax variations**

    ```js
    // One parameter, no parentheses needed
    const square = n => n * n;

    // Multiple parameters
    const add = (a, b) => a + b;

    // Multiple lines need return and braces
    const greet = name => {
      const message = `Hello ${name}`;
      return message;
    };
    ```

    **this behavior**

    ```js
    const obj = {
      name: "Aniket",
      regular: function() {
        console.log(this.name); // "Aniket"
      },
      arrow: () => {
        console.log(this.name); // undefined (or window/global)
      }
    };
    ```

    Arrow functions inherit `this` from the outer scope. This makes them great for callbacks and React event handlers.
  </Accordion>
</Accordions>

## 10. Template literals

**Q: What are template literals?**

**Why asked**: Modern string usage.

**Answer:**  
Template literals allow us to write variables inside a string easily.  
We use backticks instead of quotes.  
It also supports multi-line strings.

**Example:**
```js
const name = "Aniket";
console.log(`Hello ${name}`);
```

<Accordions type="single">
  <Accordion title="More">
    **Basic usage**

    ```js
    const name = "Aniket";
    const age = 28;

    console.log(`My name is ${name} and I am ${age} years old.`);
    ```

    **Multi-line**

    ```js
    const message = `
      Hello Aniket,
      Welcome to the team!
    `;
    ```

    **Expressions inside**

    ```js
    const a = 5;
    const b = 10;
    console.log(`Sum is ${a + b}`); // Sum is 15
    console.log(`Max is ${Math.max(a, b)}`);
    ```

    **Tagged templates** (advanced)
    You can pass a template literal to a function for custom processing (used in libraries like styled-components).
  </Accordion>
</Accordions>
