# React.js Advanced

**Difficulty**: Intermediate – Advanced  
**Revision Tip**: Build a small app using these concepts.

## 1. Lazy Loading

**Q: What is Lazy Loading in React?**

**Why asked**: Performance optimization.

**Answer:**  
Lazy Loading means loading a component only when it is needed.  
It helps improve the initial loading speed of the application.  
We use React.lazy and Suspense for this.

**Example:**
```js
const Home = React.lazy(() => import("./Home"));
```

<Accordions type="single">
  <Accordion title="More">
    ```js
    import { Suspense, lazy } from "react";

    const Home = lazy(() => import("./Home"));

    function App() {
      return (
        <Suspense fallback={<div>Loading...</div>}>
          <Home />
        </Suspense>
      );
    }
    ```

    Useful for code splitting and large applications.
  </Accordion>
</Accordions>

## 2. Context API

**Q: What is Context API?**

**Why asked**: Avoiding prop drilling.

**Answer:**  
Context API is used to share data across many components.  
It helps us avoid prop drilling.  
We create a context and provide the value at the top level.

**Example:**
```js
const ThemeContext = React.createContext();
```

<Accordions type="single">
  <Accordion title="More">
    ```js
    const ThemeContext = createContext("light");

    function App() {
      return (
        <ThemeContext.Provider value="dark">
          <Toolbar />
        </ThemeContext.Provider>
      );
    }

    function Toolbar() {
      const theme = useContext(ThemeContext);
      return <div>{theme}</div>;
    }
    ```

    Good for theme, auth, language, etc. For very complex state, consider Redux or Zustand.
  </Accordion>
</Accordions>

## 3. Hooks

**Q: What are Hooks in React?**

**Why asked**: Modern React foundation.

**Answer:**  
Hooks allow us to use state and other React features in functional components.  
The most common hooks are useState and useEffect.  
Hooks make functional components very powerful.

**Example:**
```js
const [count, setCount] = useState(0);
```

<Accordions type="single">
  <Accordion title="More">
    Common hooks:
    - `useState` → state
    - `useEffect` → side effects
    - `useContext` → context
    - `useRef` → mutable value / DOM reference
    - `useMemo` / `useCallback` → performance

    Rules of hooks:
    - Only call at the top level
    - Only call from React functions
  </Accordion>
</Accordions>

## 4. HOC (Higher Order Component)

**Q: What is a Higher Order Component?**

**Why asked**: Reusing logic.

**Answer:**  
A Higher Order Component is a function that takes a component and returns a new component.  
It is used to share common logic between components.

**Example:**
```js
function withAuth(Component) {
  return function (props) {
    return <Component {...props} />;
  };
}
```

<Accordions type="single">
  <Accordion title="More">
    HOCs were popular before hooks.  
    Today many cases are solved more cleanly with custom hooks.

    Still useful to understand for older codebases and interviews.
  </Accordion>
</Accordions>

## 5. props.children

**Q: What is props.children?**

**Why asked**: Composition pattern.

**Answer:**  
props.children allows a component to receive and display whatever is passed between its opening and closing tags.  
It is very useful for wrapper components.

**Example:**
```js
function Card({ children }) {
  return <div className="card">{children}</div>;
}
```

<Accordions type="single">
  <Accordion title="More">
    ```js
    <Card>
      <h2>Title</h2>
      <p>Content goes here</p>
    </Card>
    ```

    This is how many UI libraries create flexible layout components.
  </Accordion>
</Accordions>

## 6. Redux

**Q: What is Redux?**

**Why asked**: Global state management.

**Answer:**  
Redux is a state management library.  
It stores the entire application state in one central place called the store.  
We use actions and reducers to update the state.

**Example:**
```js
const store = createStore(reducer);
```

<Accordions type="single">
  <Accordion title="More">
    Core concepts:
    - Store → single source of truth
    - Action → plain object describing what happened
    - Reducer → pure function that returns new state

    Modern Redux uses Redux Toolkit (`createSlice`, `configureStore`) which is much simpler.
  </Accordion>
</Accordions>

## 7. Redux Thunk

**Q: What is Redux Thunk?**

**Why asked**: Async actions in Redux.

**Answer:**  
Redux Thunk is a middleware.  
It allows us to write asynchronous logic inside Redux.  
We commonly use it for API calls.

**Example:**
```js
const fetchData = () => {
  return async (dispatch) => {
    const data = await api.getData();
    dispatch({ type: "SET_DATA", payload: data });
  };
};
```

<Accordions type="single">
  <Accordion title="More">
    Without Thunk, action creators can only return plain objects.  
    Thunk lets them return functions so we can do async work before dispatching.
  </Accordion>
</Accordions>

## 8. Redux Saga

**Q: What is Redux Saga?**

**Why asked**: Advanced side-effect management.

**Answer:**  
Redux Saga is another middleware for handling side effects.  
It uses generator functions.  
It is more powerful than Thunk for complex asynchronous flows.

**Example:**  
We write sagas using `function*` and `yield`.

<Accordions type="single">
  <Accordion title="More">
    Saga is better when you have complex flows (race conditions, cancellation, retries).

    For most apps, Thunk or RTK Query is enough.
  </Accordion>
</Accordions>

## 9. Redux Form

**Q: What is Redux Form?**

**Why asked**: Historical knowledge.

**Answer:**  
Redux Form was a library used to manage form state in Redux.  
Nowadays most people use React Hook Form or Formik instead.  
It kept form data inside the Redux store.

<Accordions type="single">
  <Accordion title="More">
    Prefer **React Hook Form** today — better performance and less boilerplate.
  </Accordion>
</Accordions>

## 10. Unit Testing in React

**Q: How do you do unit testing in React?**

**Why asked**: Testing skills.

**Answer:**  
We test React components using tools like Jest and React Testing Library.  
We check if the component renders correctly and if user interactions work.

**Example:**
```js
test("renders heading", () => {
  render(<App />);
  expect(screen.getByText("Hello")).toBeInTheDocument();
});
```

<Accordions type="single">
  <Accordion title="More">
    React Testing Library encourages testing from the user’s perspective (what is on the screen) instead of implementation details.

    Common queries: `getByText`, `getByRole`, `getByTestId`.
  </Accordion>
</Accordions>
