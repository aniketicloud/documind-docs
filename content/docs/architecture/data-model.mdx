## Documents

`documents`

| Column | Notes |
|--------|--------|
| `id` | UUID text |
| `user_id` | Owner FK |
| `name` | Original filename |
| `key` | S3 object key |
| `content_type`, `size` | Metadata |
| `status` | `pending` \| `ready` \| `processing` \| `indexed` \| `failed` |
| `error_message` | Last ingest / pipeline error (if any) |
| `processed_at` | When ingest last succeeded |
| `ingest_attempts` | Worker attempt counter |

### Ingest jobs

`document_jobs` — async work items (`queued` / `running` / `succeeded` / `failed`), attempts, locks, last error.

## Chat

`chats` — conversation headers (`title`, `user_id`, timestamps)

`chat_messages` — `role` (`user` \| `assistant`), `content`, `chat_id`

`chat_message_documents` — many-to-many message ↔ document (history of turn attachments)

`chat_documents` — many-to-many **chat ↔ document** (pinned RAG scope for the whole conversation)

Deleting a chat cascades messages and chat_documents; **documents remain**.

## Vectors (not in Postgres)

Qdrant collection (default `documind_chunks`): points with **768-d** vectors from **`gemini-embedding-2`** (configurable via `GEMINI_EMBED_DIMENSIONS`) and payload  
`{ userId, documentId, documentName, chunkIndex, text }`.

If you change embed model or dimensions, re-ingest documents. Plain-language guide: [Embeddings & Qdrant](/docs/guide/embeddings-and-qdrant).
