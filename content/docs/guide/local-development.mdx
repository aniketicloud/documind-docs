## Recommended terminals

1. **Docker** — keep compose running  
2. **App** — `npm run dev` in `documind`  
3. **Ingest worker** — `npm run worker:ingest` in `documind` (needed for document `indexed` status)  
4. **Docs** (optional) — `npm run dev` in `documind-docs` on port **3001**  

Without the worker, uploads still save files, but documents may stay **`processing`**.  
See [Document ingest](/docs/guide/document-ingest) for a plain-language explanation.

## Ports cheat sheet

| Port | Service |
|------|---------|
| 3000 | Documind Next.js app |
| 3001 | Documind docs (this site, local) |
| 5433 | Postgres |
| 6379 | Redis |
| 9000 | RustFS S3 API |
| 9001 | RustFS console (`rustfsadmin` / `rustfsadmin`) |
| 6335 | Qdrant HTTP |

## Typical feature loop

1. Branch in `documind`  
2. Change API / UI / schema  
3. `npm run typecheck`  
4. Manual test (auth, chat, upload, redis)  
5. Update docs in `documind-docs` when behavior or env changes  

## UI stack notes

- **shadcn/ui** (Radix Nova style), Tailwind CSS 4  
- Chat primitives: MessageScroller, Message, Bubble, Attachment, Marker  
- Shared patterns: Spinner, Empty, AlertDialog  

See [UI conventions](/docs/development/ui).

## Agent / AI coding

`documind/AGENTS.md` reminds agents to read Next.js 16 docs under `node_modules/next/dist/docs/` before changing framework APIs.

## Full AI path (B2+B3)

1. `docker compose up -d` (includes Qdrant)  
2. Set `GEMINI_API_KEY` in `.env`  
3. `npm run dev` + `npm run worker:ingest`  
4. Upload a `.txt` / `.md` → wait for **indexed** → chat with library attach  

See [RAG chat](/docs/guide/rag-chat) for what we built and why.
