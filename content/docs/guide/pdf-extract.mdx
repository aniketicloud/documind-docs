# PDF extract & OCR (F1 + F1b)

This page explains **how** Documind turns PDFs into searchable text for chat, and **why** we built it this way — so you can explain it to others without jargon.

---

## The problem in one sentence

Chat can only answer from **text**. Many PDFs are **pictures of pages** (scans). Those have **no selectable text**, so we need **OCR** (optical character recognition) — software that “reads” the image and types out the words.

---

## Two kinds of PDF

| Kind | What it is | What we do |
|------|------------|------------|
| **Text PDF** | You can select/copy words in a PDF reader | **Fast path:** pull the text out directly (**PyMuPDF**) |
| **Scanned PDF** | Each page is basically an image | **OCR path:** render page → **Tesseract** (free, local) |

Most “born digital” PDFs (exports from Word, reports, invoices) are text PDFs.  
Phone photos of paper, or many scanner outputs, are scanned PDFs.

---

## How it works (simple flow)

```text
You upload a PDF
       ↓
Stored in RustFS (fast; no heavy work yet)
       ↓
Docker “ingest-worker” picks up a job
       ↓
Calls Docker “pdf-extract” service
       ↓
  1) Try native text (PyMuPDF)     ← free, seconds
  2) If almost no text and mode=auto
        → render pages → Tesseract OCR  ← free, slower
       ↓
Worker chunks the text → embeds → Qdrant
       ↓
Status: indexed  (ready for chat)
   or: failed    (still no useful text)
```

You still only run:

```bash
docker compose up -d
npm run dev
```

No separate OCR install on Windows — it’s **inside Docker**.

---

## Why we designed it this way

### 1. Upload stays fast

We **never** OCR inside the browser upload request. That would hang the UI.  
Heavy work runs in the **background** (same idea as the rest of ingest).

### 2. One service, two strategies (no rework later)

We did **not** build “text PDF app” then throw it away for OCR.

| Stage | What we shipped |
|-------|-----------------|
| **F1** | Native text only (`ocr=off`) |
| **F1b** | Same API: `ocr=auto` / `force` with Tesseract |

The HTTP contract stayed:

```http
POST /extract?ocr=auto
Content-Type: application/pdf
→ { text, pageCount, method, ocrUsed, warnings, reason }
```

Node only cares: **“give me plain text.”** It does not care *how* text was obtained.

### 3. Free and open source

| Tool | Role | Cost |
|------|------|------|
| **PyMuPDF** | Native text | Free / local |
| **Tesseract** | OCR engine (reads page images) | Free (Apache-2.0) |
| **Pillow + pytesseract** | Image bridge to Tesseract | Free / OSS |
| **No** Google Vision / AWS Textract | — | Avoided (paid / data leaves machine) |

### 4. Smart default: `auto`

| Mode | Meaning |
|------|---------|
| **`auto`** (default) | Try native first; OCR only if text is too thin |
| **`off`** | Native only (debug / fastest) |
| **`force`** | Always OCR (slow; for broken “fake” text layers) |

So normal text PDFs stay **fast**. Scans pay the OCR cost only when needed.

### 5. Protect free machines

OCR is **CPU-heavy**. Caps:

| Cap | Default | Why |
|-----|---------|-----|
| `PDF_OCR_MAX_PAGES` | **30** | Don’t OCR a 300-page scan by accident |
| `PDF_EXTRACT_TIMEOUT_MS` | **300000** (5 min) | Allow slow jobs without hanging forever |
| Language | **`eng`** | Smaller Docker image |

---

## What you tell someone in 30 seconds

> “We store the PDF first. A background worker asks a small Docker service for text. If the PDF already has real text, we take it instantly. If it’s a scan or screenshot PDF, the service turns each page into an image and runs free open-source Tesseract OCR. Then we chunk, embed, and answer questions. Nothing is sent to a paid OCR cloud.”

---

## Statuses you’ll see

| Status | Meaning |
|--------|---------|
| **processing** | Worker is extracting (OCR can take a while) |
| **indexed** | We got enough text and built search vectors |
| **failed** | Still almost no text (blank scan, bad quality, encrypted PDF, service down) |

**Retry ingest** on My documents after fixing Compose or re-uploading.

---

## Modes and env (operators)

| Variable | Default | Used by |
|----------|---------|---------|
| `PDF_OCR_MODE` | `auto` | **ingest-worker** → query param `ocr=` |
| `PDF_EXTRACT_URL` | host `http://127.0.0.1:8090` | Host tools; worker overrides to `http://pdf-extract:8090` |
| `PDF_EXTRACT_TIMEOUT_MS` | `300000` | Node HTTP client |
| `PDF_OCR_MAX_PAGES` | `30` | pdf-extract container |
| `PDF_OCR_LANG` | `eng` | Tesseract language |

Rebuild after code changes:

```bash
docker compose build pdf-extract ingest-worker
docker compose up -d pdf-extract ingest-worker
```

## API (pdf-extract)

| Method | Path | Notes |
|--------|------|--------|
| `GET` | `/health` | Includes `ocr: true` when F1b image is up |
| `POST` | `/extract?ocr=off\|auto\|force` | Body = raw PDF bytes |

---

## Limits (honest)

- OCR quality is **good enough for many scans**, not perfect (skew, handwriting, multi-column).  
- Long scans are **slow** — that is normal.  
- **DOCX** is handled in the Node worker with **Mammoth** (not this Python service).  
- **Sources footer** shows which chunks grounded each answer (shipped with P1.7).
