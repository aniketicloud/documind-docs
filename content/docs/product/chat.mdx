## Routes

| Route | Purpose |
|-------|---------|
| `/new` | Empty composer; no chat row until first send |
| `/c/[id]` | Existing conversation |
| `/documind` | Legacy redirect → `/new` |

## Why streaming RAG (not placeholders)

Documind’s value is **answers grounded in your files**. Placeholders would train users that “chat works” while ignoring uploads. We therefore:

1. Persist the **user** message first  
2. Retrieve chunks only from **selected, indexed** docs for this send  
3. Stream model tokens into the UI  
4. Persist the full **assistant** message **plus sources** (retrieved chunks) when the stream ends  
5. Show a **Sources** footer under the assistant bubble (doc name, chunk index, score)

Deep dive: [RAG chat](/docs/guide/rag-chat) · [ADR-0008](/docs/adr/0008-gemini-streaming-rag).

## Creating a chat

1. User types and/or adds documents on `/new` (they appear in the **documents panel**)  
2. **Send** calls `POST /api/chats/stream` with `documentIds` = **checked** files  
3. Server creates `chats` + user message (no placeholder assistant) and pins those docs  
4. Tokens stream **on `/new`** into the live assistant bubble  
5. When the stream finishes, client seeds a **handoff** and `router.replace` → `/c/{id}`  
6. `/c/{id}` paints from handoff immediately, then revalidates from the API  
7. Double-submit blocked with a sync lock while streaming  

## Continuing a chat

- `POST /api/chats/:id/messages/stream` with `documentIds` = currently **selected** panel docs  
- Unselected pins stay in the chat list but are **not** sent for RAG  
- User message stored first; assistant streams then saves  

## Model selector

- Composer dropdown: **GLM 4.7 Flash** (Z.AI) and/or **Gemini 3.1 Flash-Lite** when keys are set  
- Choice is sent as `modelId` and remembered in `localStorage`  
- Server default: `DEFAULT_CHAT_MODEL` (typically `glm-4.7-flash`)  
- `GET /api/models` returns only configured providers  

## Documents panel (collapsible)

Files for the chat live in a **panel under the header, above the messages** — not as chips in the composer.

### Why this layout

| Chips in the input | Panel above messages |
|--------------------|----------------------|
| Crowded; hard to show status | Room for badges and checkboxes |
| Easy to confuse with “this one message only” | Clear “files in this chat” |
| Awkward multi-select | Select / deselect for each answer |
| Mixes with typing | Composer stays clean |

### Panel behavior

| Control | What it does |
|---------|----------------|
| **Collapse / expand** | Chevron (primary-colored) toggles the list for more message space; preference saved in `localStorage` (`documind:docs-panel-open`) |
| **Collapsed summary** | Still shows file count and how many are selected |
| **Checkbox** | Include this file in the **next** answer’s RAG set |
| **Status badge** | Indexed / Processing… / Failed / Uploading… |
| **Remove (X)** | Remove from **this chat only** (file stays under My documents) |
| **Paperclip / folder** | Add files into the panel (upload or library) |

### Status while OCR runs

A scan may show **Processing…** for a while. You can still send a message; if a selected file is not **Indexed** yet, RAG will not invent content from it (honest “not ready” style answer). When status becomes **Indexed**, ask again with it checked.

### Server model

| Concept | Storage / API |
|---------|----------------|
| Pins (list membership) | `chat_documents` via `/api/chats/:id/documents` |
| Selection for this answer | Client sends as `documentIds` on stream requests |
| Actually retrieved | Subset of those IDs with status **`indexed`** |

## RAG product rules

| Rule | Behavior |
|------|----------|
| **Selected for send** | Only **checked** panel docs are sent as `documentIds` |
| **Indexed only** | Among those, only `indexed` contribute Qdrant chunks |
| **Deselected** | Still listed in the chat; ignored for that answer |
| **Removed** | Unpinned from chat; not deleted from the library |
| **No selection + text** | General chat (no document retrieval) |
| **Selection only** | Can send without typing (e.g. “summarize”) |
| **Sources footer** | After a grounded answer, chips list each retrieved chunk (hover for snippet) |

## Sources footer

| What you see | Meaning |
|--------------|---------|
| **Sources** label | This reply used document retrieval |
| File name + `§N` | Which file and chunk index |
| Score | How similar the chunk was to your question |
| Hover | Short text preview of that chunk |

Stored on `chat_messages.sources` (JSONB). Reload a chat later and the same citations remain.
