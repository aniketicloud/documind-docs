---
title: "ADR-0007: No document parsing on upload"
description: Defer text extraction and RAG to async workers.
---

## Status

Accepted

## Context

Parsing PDF/Office on the upload request path blocks UX and does not scale. Qdrant is available for later embeddings.

## Decision

Upload only stores objects + metadata. Parsing/chunking/embedding will be an async pipeline (e.g. Redis jobs + specialized extractors) when chat-with-doc is implemented.

## Consequences

- Pros: reliable, fast uploads; worker can scale independently  
- Cons: documents are not searchable until ingest completes  

## Follow-up (implemented)

Option **A** added the async worker and statuses. Options **B2/B3** run extract → embed → Qdrant in that worker and stream Gemini answers for **indexed** text docs. See [ADR-0008](/docs/adr/0008-gemini-streaming-rag).
